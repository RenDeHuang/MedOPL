# OPL v20.31 继承矩阵

日期：2026-05-03
目标镜像 tag：`opl-v20.31`

## 说明

v20.31 必须继承 v20、v20.1、v20.2 的商业能力。本文用于防止 v20.31 修 Portal、账务和 OPL run 时打掉前序功能。

状态定义：

- `待验证`：已有代码或计划，但本轮尚未新跑验证命令。
- `需开发`：v20.31 仍需补代码或脚本。
- `待云端终验`：本地可验证，云端 live 或 T+1 证据尚未完成。
- `阻断`：不关闭就不能推云或不能声明商业化可用。

## 推云前检查清单

- 本地 P0 smoke 通过。
- Portal build/typecheck 通过。
- OPL bridge 和 runner check 通过。
- Secret hygiene 通过。
- Sentrux 结构观察已记录。
- 镜像仓库容量和 tag 策略明确。
- kubeconfig 可用，且知道会覆盖当前线上临时 recovery 镜像。
- 资源清理不会删除承载平台 Pod 的节点。

## 当前结论

v20.31 当前处于开发推进状态。前序能力必须保留，但本轮尚未完成 v20.31 的新鲜验证，因此不能声明已可商业化上线，也不能声明可以推云。推云判断必须等 P0 本地合约、构建、secret hygiene、组件连通性脚本和资源清理边界确认后再做。
