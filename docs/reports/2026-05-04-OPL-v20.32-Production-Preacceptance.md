# OPL v20.32 生产前验收

日期：2026-05-04

## 为什么做

v20.32 的目标不是继续验证旧线上版本，而是在正式域名 `portal.medopl.cn`、`opl.medopl.cn`、`trace.medopl.cn` 上证明最小商业闭环可运营：用户选择套餐、开通存储和计算节点、Portal 记录资源归属和五个分账标签、OPL 可以收发消息和产出文件、Portal 能看到文件/账单/轨迹，删除资源后同日预扣停止。T+1 COS 精确归因和 Sentrux 绝对阈值本轮后置，但不能用它们掩盖主链路是否可用。

## 验收边界

本方案分三层执行：

1. 不产生 CVM 费用的生产前验收：登录、全组件全链接、页面渲染、关键 API、`/portal/opl` 跳转、Trace 业务页面、体验耗时。
2. OPL 消息验收：Portal 进入 OPL、gflabtoken 绑定、原生发送按钮、adapter 消息 API、OPL 回复、artifact 和 trace 记录。该层可能产生模型调用费用。
3. 真实资源全链路：创建测试用户、充值、开通存储、创建计算节点、上传文件、跑任务、下载输出、查看账单和轨迹、删除节点池并停止预扣。该层会创建和删除真实云资源，必须显式确认。

不包含：

- T+1 COS 精确账单归因。
- 新增 DNS 解析。
- Sentrux 阈值达标工程。
- 修改上游 one-person-lab runtime。

## 如何开发

新增 `scripts/live-test-v20.32-production-preacceptance.mjs` 作为 v20.32 生产前验收入口。它只读访问正式域名，默认 `skip`，只有 `RUN_V20_32_PREACCEPTANCE=1` 才执行。脚本固定校验 `portal.medopl.cn`、`opl.medopl.cn`、`trace.medopl.cn`，支持 `V20_32_CONNECT_HOST` 做隔离传输，但不要求新增 v20.32 子域名。

增强 `scripts/live-test-v20.32-isolated-full-loop.mjs` 的阶段证据，每个阶段统一写入：

- `stage`
- `startedAt`
- `endedAt`
- `latencyMs`
- `ok`
- `costRisk`

这样验收报告能回答“小白用户等了多久”：登录多久、页面渲染多久、Portal 跳 OPL 多久、OPL 首次/完整回复多久、上传下载多久、创建和删除资源多久。

不产生真实 CVM 费用的验收：

```bash

V20_32_PORTAL_BASE_URL=https://portal.medopl.cn \
V20_32_OPL_BASE_URL=https://opl.medopl.cn \
```

## 交付标准

可以说“进入生产候选”的条件：

- v20.32 生产前验收通过，证据写入 `.runtime/v20.32-production-preacceptance/`。
- OPL 消息验收通过，证据包含 `firstReplyLatencyMs` 和 `completeReplyLatencyMs`。
- 真实资源全链路通过，证据包含资源订单、CVM/存储绑定、五个分账标签、文件上传下载、账单/轨迹可见、删除后停止预扣。
- 云上只读核对证明正式 Ingress 三个 host 指向正确 service，目标 deployment ready 且镜像 tag 属于 v20.32。
- rollback 方案已确认。

不能说“可商业化生产”的情况：

- 只跑了页面验收，未跑真实资源创建删除。
- 只证明镜像 tag，没有证明用户链路。
- OPL 回复、文件产物、Portal 账单或 trace 任一环缺证据。
- `/healthz` 或 `/version` 证据落到集群/API server 语义，不能证明应用 build。

## 当前已知风险

- 2026-05-04 不创建资源验收已通过，最新证据在 `.runtime/v20.32-production-preacceptance/2026-05-04T09-15-32-991Z.json`。体验耗时偏高：Portal->OPL 跳转约 75.0 秒，Trace 首页约 2.6 秒，最慢 Portal 页面约 22.0 秒，最慢 API 约 8.8 秒。功能可用不等于小白体验达标，后续应优化 OPL 首次进入链路和 Portal 页面首屏。
- OPL 消息验收已通过，真正消息 API 回复约 4.1 秒；耗时主要出现在进入 OPL、绑定和页面可交互之前。
- 第二轮不创建资源验收曾出现 `/portal/app/billing` 200 但页面正文为空的失败，脚本已改为等待每页业务文字出现后再判定。最新第三轮通过，说明该项目前可通过，但仍暴露页面渲染稳定性和首屏耗时风险。
- 参数化管理员详情页 `/admin/user`、`/admin/workspace`、`/admin/run` 不是侧边栏一级入口，生产前验收应通过 `admin/users`、`admin/usage` 等页面里的实际链接覆盖，不能只看 router 存在。
- Trace 的 Kubernetes probe 仍是 TCP，不是业务健康 HTTP 路径；生产前验收改用业务首页和 Portal trace API 证明可用。
- `langfuse-web` 曾有重启记录，需要结合只读日志确认原因。
- Sentrux `quality_signal` 和 `modularity` 仍未达到绝对阈值，但当前 DSM 无循环、依赖方向干净；结构债后置。
