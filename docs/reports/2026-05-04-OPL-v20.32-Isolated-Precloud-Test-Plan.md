# OPL v20.32 Isolated Precloud Test Plan

日期：2026-05-04

目标版本：`opl-v20.32`

## 结论

v20.32 推云前测试不能把当前旧线上版本当作 v20.32 证明闭环。正式入口域名固定为 `portal.medopl.cn`、`opl.medopl.cn`、`trace.medopl.cn`，不新增 `portal-v20-32.*` 或 `opl-v20-32.*` DNS。隔离性由显式 transport 路径和 build tag 校验保证：脚本用正式 host 发请求，但实际连接必须通过 `V20_32_CONNECT_HOST` 指向 v20.32 隔离入口，并且先读 Portal `/healthz` 确认 build tag 为 `opl-v20.32` 后才允许创建用户或资源。

推荐隔离目标：

- Platform namespace：`portal-v20-32-staging`
- Runtime namespace：`portal-runtime-v20-32-staging`
- Portal host：`portal.medopl.cn`
- OPL host：`opl.medopl.cn`
- Trace host：`trace.medopl.cn`
- 隔离传输：`V20_32_CONNECT_HOST=<v20.32 ingress/LB/proxy>`，可选 `V20_32_CONNECT_PORT=443`

单 VM 只能做浏览器自动化、只读回归和跳板机，不适合作为完整商业闭环承载面。完整闭环需要真实 Ingress、K8s RBAC、runtime Job、resource provisioner、TKE node pool、CVM、COS 存储和账单链路。

## 推云前执行顺序

### 1. 本地合约

```bash
node scripts/smoke-test-v20.32-user-resource-binding-contract.mjs
node scripts/smoke-test-v20.32-package-minimal-loop-contract.mjs
node scripts/smoke-test-v20.32-portal-opl-message-loop-contract.mjs
node scripts/smoke-test-v20.32-isolated-full-loop-contract.mjs
npm --prefix services/portal run check
npm --prefix services/portal/frontend run typecheck
npm --prefix services/portal/frontend run build
sentrux check .
```

### 2. 只读云前置

推荐直接跑自动化只读 readiness：

```bash
V20_32_KUBECONFIG=/home/dev/.secrets/medopl/kubeconfig-v20.32-external \
node scripts/check-v20.32-cloud-readiness.mjs
```

只读检查包括：

```bash
kubectl get ns
kubectl get nodes
kubectl auth can-i create deployments -n portal-v20-32-staging
kubectl auth can-i delete deployments -n portal-v20-32-staging
kubectl auth can-i create jobs -n portal-runtime-v20-32-staging
```

当前 `/home/dev/.secrets/medopl/kubeconfig-v20.32-external` 已通过只读 readiness；不要使用会超时的 `/home/dev/.secrets/medopl/kubeconfig-v20.32` 执行 apply 或 rollout。

### 3. 构建计划 dry-run

```bash
node deploy/tke-package/scripts/build-and-push-tcr.mjs \
  --tag opl-v20.32 \
  --skip-login 1 \
  --allow-tracked-env 1 \
  --manifest-out-dir deploy/tke-package/rendered-v20.32-plan \
  --runner-workload-image uswccr.ccs.tencentyun.com/gaofenglab/med-autoscience-runner-opl:opl-v20.32
```

该命令只输出计划，不执行 `docker build`、`docker push` 或 `kubectl apply`。

### 4. 隔离 env 文件

需要生成非 tracked 的 v20.32 env 文件，至少改：

- `BUILD_SHA=opl-v20.32`
- `NAMESPACE=portal-v20-32-staging`
- `RUNTIME_NAMESPACE=portal-runtime-v20-32-staging`
- `PORTAL_HOST=portal.medopl.cn`
- `OPL_HOST=opl.medopl.cn`
- 所有镜像变量统一为 `:opl-v20.32`
- `RESOURCE_PROVISIONING_ENABLED=1`
- `TENCENT_TKE_CLUSTER_ID`
- `TENCENT_VPC_ID`
- `TENCENT_SUBNET_IDS`
- `TENCENT_SECURITY_GROUP_ID`
- `TENCENT_TKE_NODE_IMAGE_ID`
- `PORTAL_POSTGRES_URL`
- `PORTAL_REDIS_URL`
- `OPL_LAUNCH_SECRET`
- `PORTAL_INTERNAL_AUTH_TOKEN`
- `MED_AUTOSCIENCE_RUNNER_TOKEN`

### 5. 会改变云端状态的动作

以下动作会产生费用或改变云端状态，需要明确执行窗口和清理策略：

```bash
docker login
docker build
docker push
kubectl apply -f <rendered-v20.32-plan>
kubectl rollout restart/status
RUN_V20_32_FULL_LOOP=1 node scripts/live-test-v20.32-isolated-full-loop.mjs
```

完整 live gate 会创建 1 名测试用户、充值、开通存储、创建资源订单、触发 TKE 节点池/CVM、使用 OPL、上传/下载文件、删除节点池并销毁 CVM。

## 完整闭环断言

`scripts/live-test-v20.32-isolated-full-loop.mjs` 覆盖：

1. `admin_user_create`：管理员创建测试用户。
2. `wallet_topup`：管理员充值。
3. `portal_login`：测试用户登录 Portal。
4. `storage_order`：测试用户开通 COS 存储。
5. `workspace_upload`：测试用户上传 workspace 文件。
6. `resource_quote`：报价资源订单。
7. `resource_freeze`：冻结预扣费。
8. `resource_provision`：开通节点池/CVM。
9. `user_resources`：Portal 可见该用户资源，且标签包含 `resourceorderid/runid/serverplanid/tenantid/workspaceid`。
10. `opl_message`：OPL native login 使用 gflabtoken API key，发送消息并收到回复。
11. `opl_file_run`：OPL 启动文件任务并产出 artifact。
12. `workspace_download`：Portal 下载输出文件。
13. `billing_trace`：Portal 能看到账单和 session trace。
14. `delete_node_pool`：仅按 `resourceOrderId` 删除节点池，不向后端传 `nodePoolId`。
15. `billing_stop_observe`：删除后读取 run 成本状态。
16. `t0_120min_checkpoint`：记录 120min 复核点。
17. `t1_audit_checkpoint`：记录 T+1 审计复核点。

## 当前 blocker

1. 仍需 build/push 新 v20.32 镜像并 rollout 到 v20.32 隔离命名空间。
2. 普通 `kubeconfig-v20.32` API server 查询超时；当前可用的是 `kubeconfig-v20.32-external`。
3. 现有 Node 打包脚本默认仍是 `opl-v20.31`，必须显式传 `--tag opl-v20.32` 和 `--manifest-out-dir deploy/tke-package/rendered-v20.32-plan`。
4. 当前 secrets 里有 TCR、COS、Billing 和 kubeconfig 变量；实际 build/push 时可由 readiness 把 `TCR_SECRET` 本地映射为 `TCR_PASSWORD`，不要把值写入文档或输出。
5. T+1 COS 精准账单归因不是 v20.32 推云 blocker；生产前仍必须跑通 same-day 资源绑定、预扣、OPL 消息/文件/下载、删除停费和 trace 可见性。
