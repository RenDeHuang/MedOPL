# OPL v20.3 待验证

日期：2026-05-03
时区：Asia/Shanghai
目标版本：`opl-v20.3`

## 结论

v20.3 当前是“本地硬化已完成一部分、云端终验阻断”的状态，不能标记为公开商业化上线。

本轮没有部署 `opl-v20.3`，没有创建付费云资源，没有删除云资源，也没有跑全量 live E2E。原因是云端只读探测已经暴露基础连接问题：

- `portal.medopl.cn/login` 10 秒无响应。
- `portal.medopl.cn/healthz` 10 秒无响应。
- `trace.medopl.cn/healthz` 返回 404。
- TKE API 只读 `kubectl get` 多次 `context deadline exceeded` 或连接 reset。

因此现在不能证明 Portal 真实渲染、不能证明 Portal/OPL/Trace 三站 session 打通，也不能安全推进会产生费用的 live gate。

## 当前阻断

### 阻断 1：Portal 公网不可用

`https://portal.medopl.cn/login` 与 `/healthz` 10 秒无响应。没有 Portal，无法验证登录、充值、workspace、账单、真实渲染、文件查看和 trace 回查。

### 阻断 2：Trace health 返回 404

`https://trace.medopl.cn/healthz` 返回 404。需要确认 Trace 的健康路径是否不同，还是 ingress/service 未接入。

### 阻断 3：TKE API 只读查询不稳定

kubectl 只读查询出现 `context deadline exceeded` 和连接 reset。当前不能安全执行 migration、部署、pod 查看或资源清理确认。

### 阻断 4：T+1 时间窗口

即使 same-day live 后续跑通，也必须等待覆盖 v20.3 run 的 T+1 账单对象到达，才能做 exact reconcile。

## 下一步建议

1. 先恢复 TKE API 和 Portal ingress 可用性。
2. 执行 `npm --prefix services/portal run migrate:schema`。
3. 部署 `opl-v20.3`。
4. 先跑只读 13 条连通性矩阵。
5. 把 `portal-rendering/session-trace/opl-file-run` 升级为主动操作 gate。
6. 跑 same-day live E2E。
7. 删除服务器并验证停止计费。
8. 等 T+1 账单对象回来后执行 exact reconcile。
