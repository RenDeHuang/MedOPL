## 交付与测试执行方式

### A. 生产预验收 gate（默认跳过）

脚本：`scripts/live-test-v20.34-production-preacceptance.mjs`

启用变量（全部必填）：

- `RUN_V20_34_PRODUCTION_PREACCEPTANCE=1`
- `PORTAL_BASE_URL`
- `OPL_BASE_URL`
- `TRACE_BASE_URL`

可选变量：

- `V20_34_PREACCEPTANCE_REQUEST_TIMEOUT_MS`（默认 `20000`）

命令示例：

```bash
RUN_V20_34_PRODUCTION_PREACCEPTANCE=1 \
PORTAL_BASE_URL="https://portal.medopl.cn" \
OPL_BASE_URL="https://opl.medopl.cn" \
TRACE_BASE_URL="https://trace.medopl.cn" \
node scripts/live-test-v20.34-production-preacceptance.mjs
```

检查项：

1. `portal/opl/trace` 三个 base URL 可访问。  
2. `portal /healthz`、`portal /portal/api/config`。  
3. `opl /api/health`、`trace /api/public/health`。

证据输出：

- `.runtime/v20.34-production-preacceptance/*.json`

### B. Portal->OPL->TraceId gate（默认跳过）

脚本：`scripts/live-test-v20.34-portal-opl-traceid-gate.mjs`

启用变量（必填）：

- `RUN_V20_34_OPL_TRACEID_GATE=1`
- `PORTAL_BASE_URL`
- `OPL_TEST_MESSAGE`
- `PORTAL_SESSION_COOKIE` 或 `PORTAL_BEARER_TOKEN`（二选一）

可选变量（路径与轮询）：

- `V20_34_OPL_LAUNCH_PATH`（默认 `/portal/api/opl/launch`）
- `V20_34_OPL_MESSAGE_PATH`（默认 `/portal/api/opl/message`）
- `V20_34_OPL_STATUS_PATH`（默认 `/portal/api/opl/status`）
- `V20_34_TRACE_QUERY_PATH`（默认 `/portal/api/session-traces`）
- `V20_34_OPL_POLL_INTERVAL_MS`（默认 `1500`）
- `V20_34_OPL_DEADLINE_MS`（默认 `120000`）
- `V20_34_OPL_REQUEST_TIMEOUT_MS`（默认 `30000`）

命令示例：

```bash
RUN_V20_34_OPL_TRACEID_GATE=1 \
PORTAL_BASE_URL="https://portal.medopl.cn" \
PORTAL_BEARER_TOKEN="<token>" \
OPL_TEST_MESSAGE="v20.34 live gate traceId check" \
node scripts/live-test-v20.34-portal-opl-traceid-gate.mjs
```

执行流程：

1. launch  
2. message  
3. status 轮询（固定间隔 + 明确截止时间）  
4. trace 查询（traceId 命中）

证据输出：

- `.runtime/v20.34-portal-opl-traceid-gate/*.json`

### C. Portal 全量组件点击矩阵 gate

脚本：`scripts/live-test-v20.34-portal-component-click-matrix.mjs`

正式 gate 必填：

- `RUN_V20_34_COMPONENT_CLICK_MATRIX=1`
- `V20_34_PORTAL_EMAIL`
- `V20_34_PORTAL_PASSWORD`
- `V20_34_PORTAL_BASE_URL`（默认 `https://portal.medopl.cn`，脚本强校验 host）

可选：

- `V20_34_CONNECT_HOST`
- `V20_34_CONNECT_PORT`
- `V20_34_BROWSER_PROXY`
- `V20_34_ALLOW_INSECURE_TLS=1`
- `V20_34_COMPONENT_CLICK_TIMEOUT_MS`
- `V20_34_COMPONENT_CLICK_CONTROL_TIMEOUT_MS`

dry-run：

```bash
RUN_V20_34_COMPONENT_CLICK_DRY_RUN=1 \
node scripts/live-test-v20.34-portal-component-click-matrix.mjs
```

正式运行：

```bash
RUN_V20_34_COMPONENT_CLICK_MATRIX=1 \
V20_34_PORTAL_BASE_URL="https://portal.medopl.cn" \
V20_34_PORTAL_EMAIL="<portal-email>" \
V20_34_PORTAL_PASSWORD="<portal-password>" \
node scripts/live-test-v20.34-portal-component-click-matrix.mjs
```

范围：

- 普通用户：总览、套餐、我的资源、工作空间、账单、轨迹。
- 管理员：运营总台、用户管理、客户账务、账单归因、告警中心、系统状态、云资源状态、审计等。
- 控件：按钮、链接、tab、select、checkbox、radio、summary。
- 危险动作：点击到浏览器确认层，脚本自动取消，记录 `confirmation_dismissed`。

证据输出：

- `.runtime/v20.34-portal-component-click-matrix/*.json`

## 证据路径

1. 预验收 gate：`.runtime/v20.34-production-preacceptance/`  
2. traceId gate：`.runtime/v20.34-portal-opl-traceid-gate/`
3. 组件点击矩阵：`.runtime/v20.34-portal-component-click-matrix/`

说明：

- traceId gate 和生产预验收 gate 缺少环境变量或未打开开关时，会写入 `skipped` 证据并 `exit 0`。  
- 组件点击矩阵作为 release gate 时缺少开关会写入失败证据并返回非零；只有显式 `RUN_V20_34_COMPONENT_CLICK_DRY_RUN=1` 才允许跳过并返回 0。  
- 开关开启后发生接口失败/超时/状态失败，脚本会写失败证据并返回非零退出码。
