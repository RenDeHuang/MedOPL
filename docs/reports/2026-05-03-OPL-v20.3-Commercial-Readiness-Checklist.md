# OPL v20.3 商业化就绪核对清单

日期：2026-05-03
版本：v20.3
目标镜像 tag：`opl-v20.3`

## 结论

v20.3 当前进入“本地硬化开发完成、等待云端 live gate 证明”的状态。

不能声明公开商业化上线。原因是 Portal/OPL/Trace/腾讯云 13 条连接、浏览器真实渲染、same-day E2E、删除停费、T+1 exact reconcile 还没有在云端跑出通过 evidence。

## 核对项

| 项目 | 当前状态 | 证据 | 剩余工作 |
| --- | --- | --- | --- |
| 稳定性 | 部分完成 | schema migration 从请求路径隔离，新增显式迁移命令；领域 store 合约不做全表 DELETE | 真实路由仍有 `writeDb(db)` 兼容路径，需云端稳定窗口证明无 deadlock |
| 账务可信 | 部分完成 | `topupWallet/chargeWallet/refundWallet/makeupChargeWallet` 单事务写 wallet、ledger、audit，幂等合约通过 | 真实账单三视图一致性和 T+1 终验未跑 |
| 错误可理解 | 部分完成 | OPL run 失败响应改为稳定错误码、stage、correlationId，用户文案不显示底层错误 | 浏览器任务失败页仍需 live 渲染验证 |
| 运营后台聚焦 | 文档化待验证 | v20.3 文档要求管理员聚焦客户账务、云资源状态、待处理队列 | 前端信息架构仍有旧入口，需后续瘦身 |
| 证据链 | 部分完成 | live 脚本定义 tenant/workspace/run/resourceOrder/correlationId evidence | 未跑真实 Portal/OPL/Trace 三站一致性 |
| 售后边界 | 部分完成 | support boundary 合约覆盖余额、冻结、宽限期、文件保留期、失败不扣费 | 需要接入用户账单页/任务失败页并做浏览器验收 |
| 重叠功能 | 已识别 | 管理后台仍存在 admin dashboard/ops/system/usage/alerts/sandboxes 等重复入口 | v20.3 未大改，避免扩大风险；建议下一轮展示层瘦身 |
| 残留功能 | 已识别 | snapshot writer、旧 admin fallback、旧页面入口仍保留 | snapshot 仅作为兼容迁移镜像用途，P0 路由切换仍需继续 |

## 面向小白用户的硬边界

- 用户页不得直接展示 `kubectl`、`RBAC`、`TKE`、`CVM`、`COS`、`OpenCost`、`502` 等底层词。
- 用户应看到“云服务器、工作空间、文件空间、真实账单、待校准、已停止计费、需要充值”等业务语言。
- 管理员可以看到底层证据，但必须关联用户、workspace、run、账单、释放状态和处理动作。

## 当前不可宣称

- 不可宣称 `portal.medopl.cn`、`opl.medopl.cn`、`trace.medopl.cn` 已全部真实打通。
- 不可宣称 OPL 文件任务可以稳定上传、运行、下载。
- 不可宣称删除服务器后一定停止计费，直到 live gate 证明资源释放和账务停止。
- 不可宣称 T+1 精准账单已完成，直到覆盖 v20.3 run 的账单对象回来并完成 exact reconcile。

## 下一步验证

1. 部署前执行 `npm --prefix services/portal run migrate:schema`。
2. 部署 `opl-v20.3` 后跑 13 条连通性矩阵。
3. 跑 Portal 浏览器渲染 gate，检查关键页面非空、无 console error、无旧模块。
4. 跑 same-day E2E 到下载输出、删除服务器、停止计费证据。
5. 等覆盖 v20.3 run 的 T+1 账单对象回来，执行 exact reconcile。
