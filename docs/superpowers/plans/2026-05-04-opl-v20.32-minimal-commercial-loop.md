# OPL v20.32 Minimal Commercial Loop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the v20.32 minimum commercial loop: package purchase, user resource bindings, order-bound deletion, and Portal-to-OPL message verification.

**Architecture:** Keep aggregation in focused domain modules, HTTP concerns in route modules, and UI state in Vue views plus typed API functions. The deletion path is order-bound: clients submit `resourceOrderId`, the backend resolves cloud identifiers from persisted bindings.

**Tech Stack:** Node.js ESM backend, Vue 3 frontend, smoke-test contract scripts, Sentrux structural observation.

---

## Scope

This plan implements only the minimum loop approved for v20.32:

- Two default packages plus custom entry.
- Add storage and add compute node actions.
- `GET /portal/api/my/resources` for ordinary users.
- `POST /portal/api/resource-orders/delete-node-pool` rejects client-supplied cloud resource IDs.
- Portal UI shows resource bindings and deletes by order.
- Live gate validates `opl.medopl.cn` can receive a real message.

The only required billing attribution labels are:

- `resourceorderid`
- `runid`
- `serverplanid`
- `tenantid`
- `workspaceid`
