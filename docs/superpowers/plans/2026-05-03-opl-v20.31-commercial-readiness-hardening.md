# OPL v20.31 Commercial Readiness Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 v20、v20.1、v20.2 的商业能力完整继承到 v20.31，并修复 Portal 登录稳定性、账务一致性、OPL 文件任务诊断、全链路连通性和页面真实渲染这些商业化 P0 阻断项。

**Architecture:** v20.31 采用领域聚合边界推进：Portal auth/request、Portal accounting、OPL run/runner、connectivity/rendering 四条线独立开发，通过结构化 contract 和 evidence 汇合。模块间只传递明确 payload、错误码、correlationId 和业务状态，模块内部保持单一职责。

**Tech Stack:** Node.js ESM, Vue 3, TypeScript, PostgreSQL, Redis, Tencent COS/TKE/CVM, Kubernetes, Playwright/GStack browser scripts, Sentrux.

- [ ] **Step 2: 写 body abort/limit 失败测试**

测试要求：

- body 超过限制返回 `request_body_too_large`。
- req 触发 `aborted` 返回 `request_body_aborted`。
- 正常 body 返回 Buffer。

Run:

```bash
node scripts/smoke-test-v20.31-http-body-contract.mjs
```

Expected: 当前 `readBody()` 没有结构化错误时 FAIL。

- [ ] **Step 3: 改 dispatcher 顺序**

在 `portal-http-dispatcher.mjs` 中先处理认证前路由：

```js
const authHandled = await handleAuthRoutes(req, res, context);
if (authHandled) return true;
const session = await currentUser(req);
```

约束：只有无需完整用户上下文的路由可以提前处理，普通业务 API 不得绕过认证。

- [ ] **Step 4: 实现 body 错误模块**

`http-body-errors.mjs` 导出稳定错误：

```js
export class HttpBodyError extends Error {
  constructor(code, message, statusCode = 400) {
    super(message);
    this.name = "HttpBodyError";
    this.code = code;
    this.statusCode = statusCode;
  }
}

export function isHttpBodyError(error) {
  return error instanceof HttpBodyError || typeof error?.code === "string" && error.code.startsWith("request_body_");
}
```

- [ ] **Step 5: 改 `readBody`**

`readBody(req, { limitBytes = 1024 * 1024 } = {})` 在读取过程中累计大小，超限抛 `HttpBodyError("request_body_too_large", ...)`；监听 abort，抛 `HttpBodyError("request_body_aborted", ...)`。

## 9. 推云边界

可以推云：

- 本地 P0 合约和构建通过。
- Secret isolation 检查通过。
- 镜像仓库容量允许使用 `opl-v20.31`。
- kubeconfig 可用。
- 已确认 v20.31 会覆盖当前线上临时 recovery 镜像状态。

不能推云：

- 登录快路径失败。
- 账务事务失败。
- OPL run 错误契约失败。
- 构建失败。
- 发现 secret 泄露风险。
- 不能确认资源清理不会影响平台节点。

推云后不能宣称最终商业化封版，除非 same-day live E2E、删除停费、T+1 exact reconcile 都有覆盖 v20.31 目标 run 的 evidence。
