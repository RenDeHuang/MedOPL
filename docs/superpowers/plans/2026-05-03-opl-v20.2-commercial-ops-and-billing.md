# OPL v20.2 小白商业化运营实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 OPL v20.2 从“技术可用”推进到“面向小白用户可受控商业化运营”：用户能看懂套餐、存储、账单、任务和文件；管理员能看清每个客户的充值、消费、资源和风险；OPL 消息、文件任务、T+1 账单和删除停费形成可验证闭环。

**Architecture:** v20.2 必须按低耦合、高聚合、模块互不影响推进。Portal 展示层只做用户/管理员可读表达；计费策略只负责余额、冻结、预扣、精准结算和拦截；OPL 网关只负责登录、API key 传递、消息代理和 upstream 集成；资源开通模块只负责资源身份链、强绑定删除和库存证据；账单归因模块只负责 COS 账单读取、解析、归因和幂等结算。

**Tech Stack:** Node.js ESM, Vue 3, TypeScript, Vite, PostgreSQL, Redis, Tencent Cloud COS/TKE/CVM, Kubernetes manifests, Sentrux, existing smoke/live scripts.

## 4. 计费状态机

### 4.1 用户余额状态

状态枚举：

- `healthy`：余额和冻结都充足，可继续所有操作。
- `low_available_balance_freeze_covers_current_week`：可用余额偏低，但冻结资金覆盖当前周；提醒充值，允许当前服务继续，阻止新的高风险付费动作。
- `insufficient_for_next_paid_action`：可用余额和可用冻结覆盖不足以启动新的付费动作；阻止新任务和扩容，允许下载已有结果。
- `grace_download_only`：只允许下载已有结果和查看账单，不允许新建付费资源。
- `suspended`：超过宽限策略或管理员封停，阻止新付费动作；是否允许下载由文件保留策略决定。

### 4.2 计费记录状态

状态枚举：

- `reserved_weekly_freeze`：套餐购买后的本周服务保障金冻结。
- `pending_runtime_preauth`：运行中预扣。
- `waiting_exact_bill`：等待 T+1 精准账单。
- `exact_charged`：精准扣费完成。
- `exact_refunded`：精准退款完成。
- `exact_makeup_charged`：精准补扣完成。
- `unattributed`：账单行未能归因，需管理员处理。

### 4.3 用户文案规则

- 禁止普通用户一级页面出现 `K8s`、`Kubernetes`、`CVM`、`TKE`、`COS`、`node pool`、`对象存储开通`。
- 允许管理员高级详情展示技术 id。
- 所有扣费说明必须包含：买了什么、用了多久、当前是预扣还是精准结算、是否还会校准。
- 所有余额风险说明必须包含：当前服务是否继续、是否能新建任务、建议充值金额。

## 5. 页面交付边界

### 5.1 普通用户页面

- `总览`：展示套餐、余额状态、下一步动作、低余额提醒、最近任务。
- `套餐`：展示套餐名、适合场景、包含存储、可做事项、限制、扩容/充值入口。
- `工作空间`：展示文件、容量、上传、下载、任务输出，不展示“对象存储开通”。
- `账单`：展示余额、冻结、今日/本月/累计消费、充值记录、预扣、T+1 校准状态。
- `轨迹`：展示 session 对话、任务、文件输入输出关系。

### 5.2 管理员页面

- `客户账务`：一行一个客户，支持进入客户详情，展示充值、消费、冻结、资源、文件、轨迹。
- `运行资源`：展示服务器编号、任务编号、资源订单、运行/释放状态。
- `账单归因`：展示 T+1 preview/reconcile 结果、未归因原因、幂等运行记录。
- `用户管理`：保留账号、角色、状态。
- `系统状态`：展示健康检查、PostgreSQL/Redis 恢复证据、镜像版本。
- `云资源状态`：只给管理员看，展示 TKE/CVM/清理证据，不给普通用户看。
