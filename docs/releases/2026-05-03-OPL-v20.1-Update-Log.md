# OPL v20.1 Update Log

Date: 2026-05-03
Image tag: `opl-v20.1`

## Scope

v20.1 is a hardening release on top of v20. It focuses on resource deletion safety, live gate compatibility, and structural cleanup toward the Sentrux absolute threshold.

## Changes

- Strengthened Portal node pool lifecycle guards:
  - `/portal/api/resource-orders/delete-node-pool` now rejects mismatched `nodePoolId` before calling Resource Provisioner.
  - `/portal/api/resource-orders/release` with `scaleToZero=true` now uses the same order-bound node pool validation.
  - Client-supplied `tenantId`, `workspaceId`, and `serverPlanId` are not trusted for destructive actions; Portal derives them from the stored resource order.
- Strengthened Resource Provisioner destructive binding checks:
  - `deleteNodePool` now requires `resourceOrderId`, `nodePoolId`, `tenantId`, `workspaceId`, and `serverPlanId`.
  - Delete validation runs before the TKE `DeleteClusterNodePool` call.
  - Resource mapping lookup now requires all provided lookup fields to match.
  - `scaleNodePool` rejects mismatched binding metadata when binding fields are provided.
- Updated live gate delete payloads:
  - `scripts/live-test-v19-tke-create-delete-cleanup.mjs` and `scripts/live-test-v19-user-e2e.mjs` now send the full binding tuple for node pool deletion.
- Added regression coverage:
  - Portal negative cases for wrong node pool and missing node pool.
  - Resource Provisioner negative cases for missing binding fields and missing mapping.
  - Live delete payload contract for required binding fields.
- Continued Sentrux structure work:
  - Split Portal runtime domain imports into commercial, storage, provider/API-key, and presentation wiring modules.
  - Moved Portal route wiring out of `portal-runtime.mjs`.
  - Removed the unused `portal-runtime-domain.mjs` aggregation bucket.
- Fixed the Portal route wiring dependency injection missed during the split:
  - `portal-runtime.mjs` now passes `runZitadelAdminUser` into `createPortalRuntimeRouteWiring`.
  - This restores `/portal/admin/create-user` in local identity mode and prevents the misleading `ZITADEL sync failed` 502.
  - Added `scripts/smoke-test-portal-runtime-route-wiring-contract.mjs` so the wiring dependency cannot be dropped again silently.
