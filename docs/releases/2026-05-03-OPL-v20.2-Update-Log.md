## 本次改动

### Portal 产品和计费

- 补齐面向小白用户的套餐字段：套餐存储、包含能力、限制说明、超出说明和下一步建议。
- 新增确定性余额风险策略，覆盖余额充足、可用余额低但冻结覆盖本周、余额不足、只允许下载、暂停服务五类状态。
- 新增 `/portal/api/billing/me/summary`，返回余额、可用余额、本周冻结、今日/本月/累计消费、累计充值、运行中预扣和 T+1 校准说明。
- 新增管理员客户账务 API：`/portal/api/admin/customer-accounting`、`/portal/api/admin/customer-accounting/detail`。
- 拆分管理员客户账务聚合逻辑，让账务 payload 构建和 ledger 策略保持低耦合。

### Portal 结构拆分

- 删除旧聚合文件 `services/portal/src/app/portal-runtime-domain.mjs`。
- 拆分为更窄的领域模块：
  - `services/portal/src/app/portal-commercial-domain.mjs`
  - `services/portal/src/app/portal-lab-domain.mjs`
  - `services/portal/src/app/portal-presentation-domain.mjs`
  - `services/portal/src/app/portal-storage-domain.mjs`
  - `services/portal/src/app/portal-runtime-route-wiring.mjs`
- 目的：把商业套餐、套餐权益、页面表达、存储和 route wiring 分开，避免 Portal runtime 继续膨胀。

### Portal 前端

- 普通用户导航收敛到总览、套餐、工作空间、账单、轨迹。
- 工作空间、账单、轨迹、套餐页面改成普通用户能理解的语言。
- 普通用户侧不再把“对象存储开通”“K8s 运维与分发”作为主入口。
- 管理员告警改成需要行动的事项：余额不足、账单归因失败、资源释放失败、OPL key 缺失或无效、精准账单导入失败。
- 管理员运维页改成云资源状态表达，突出服务器编号、任务编号、释放证据和停止计费状态。

### OPL 集成

- 保持 `.runtime/one-person-lab-upstream` 干净，未修改 upstream runtime。
- 保持 runtime URL 合约为 `https://github.com/gaofeng21cn/one-person-lab`。
- 增加 `gflabtoken` provider key payload，来源固定为 `user_input`。
- launch payload 只携带脱敏 provider 元数据，不返回 API key 明文。
- 新增独立 OPL message callback：`/api/opl-launch/messages`。消息回复走 OPL ACP runtime `prompt`，`startRun` 继续只负责文件/计算资源任务。
- message callback 校验 provider 已配置，调用 OPL runtime 获取非空回复，把回复持久化为 `message_reply` artifact，并写入 `OPL message reply` trace。
- runtime bridge 镜像包含 upstream OPL runtime，并 pin `@openai/codex@0.128.0`，显式设置 `OPL_CODEX_BIN=/usr/local/bin/codex`。
- Adapter 为每个 provider secret ref 生成独立 `CODEX_HOME/config.toml`，将 Codex endpoint 指向 `https://gflabtoken.cn/v1`，provider 名称为 `gflab`，避免默认打到 `api.openai.com`。

### Billing Aggregator

- 增加 COS 精准账单 preview 响应合约，返回 attributed rows、unattributed rows、分支摘要和 would-charge/refund/makeup cents。
- 增加 object key 方式的精确账单回放路径，不保存 signed URL。
- 增加 run/workspace 的确定性 fallback 匹配，只有唯一匹配时才归因。
- 保持精准扣费、退款、补扣、未归因四个分支互斥且幂等。
- 将 CLI 参数解析拆成 `defaultBillingCliOptions`、`applyBillingCliOption`、`applyBillingCliAssignment`、`parseBillingCliAssignment`，降低 `parseBillingCli` 复杂度。
- 同步更新 TKE build context：`deploy/tke-package/source/adapters/billing-aggregator/src/billing-config.mjs`。

### Resource Provisioner

- 增加资源身份链和删除证据职责拆分：
  - `adapters/resource-provisioner/src/bindings.mjs`
  - `adapters/resource-provisioner/src/inventory.mjs`
  - `adapters/resource-provisioner/src/provisioner.mjs`
  - `adapters/resource-provisioner/src/store.mjs`
- 用户侧资源状态新增服务器编号、任务编号、口语化状态、使用分钟数、是否停止计费、释放时间。
- 管理员云资源状态新增 node pool、CVM instance、清理证据和云端是否仍存在。
- 删除/释放链路继续绑定已存储的资源订单身份，不信任客户端传入的 tenant/workspace/serverPlan 字段。

## 11 点问题映射

1. COS 临时签名账单地址：已改为 object key 回放；signed URL/token 不进源码、文档和 evidence。
2. 存储和账单关系：用户侧表达为套餐容量、已用容量、文件和扣费；管理员侧保留订单和归因证据。
3. 任务空间里的“对象存储开通”：普通用户侧不作为主入口；后端记录保留用于审计。
4. 运行总台关键入口：普通用户导航已收敛到核心任务路径。
5. 告警概览：普通用户侧不保留泛泛告警；管理员侧保留需要行动的告警。
6. 告警列表用途：限定为低余额、归因失败、释放失败、OPL key 缺失/无效、精准账单导入失败。
7. 待处理记录：表达为运行中预扣、等待 T+1 校准、待补扣/待退款/待归因。
8. 成本构成：拆成套餐费、服务器运行费、存储费、预扣金额、最终校准金额。
9. 管理员看每人花费和充值：新增客户账务 API 和页面合约，覆盖今日、本月、累计消费和充值。
10. K8s 运维与分发：普通用户不展示；管理员侧改成云资源状态和清理证据。
11. OPL 无回复：live gate 已通过，确认 `opl.medopl.cn` 可发送消息并得到非空回复。
